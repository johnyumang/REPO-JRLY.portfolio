# JRLY backend — Medusa v2.22.2 (self-hosted, free)

Live-mode backend for the storefront: catalogue, cart, checkout, customer auth, orders, admin dashboard.

## What `npm run seed` configures
| Setting | Value |
|---|---|
| Store name | `JRLY` (`STORE_NAME`) |
| Currency | EUR (matches storefront € prices) |
| Region | Europe: DE, FR, ES, IT, NL, BE, AT, IE, PT · system tax provider · manual payment provider |
| Sales channel | Webshop, linked to the publishable key and warehouse |
| Stock location | JRLY Warehouse (`[CITY]`, `[ADDRESS]` placeholders) |
| Shipping | Standard €4.95, **free from €50** (price rule on `item_total`) · Express €9.95 |
| Catalogue | 8 categories + 48 products / 284 variants (Color × Size) imported from `../content/catalog.ts`, same SKUs, prices and stock as the offline storefront |
| Images | `${STOREFRONT_URL}/stock/<key>-1400.webp` (served by the storefront) |

The seed runs once (it marks the store `metadata.jrly_seeded`) and prints the **publishable key** for the storefront's `NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY`.

## Run locally (Postgres 16 + Redis)
```bash
cp .env.template .env        # then set random JWT_SECRET / COOKIE_SECRET
npm install
npx medusa db:migrate
npm run seed
npx medusa user -e admin@example.com -p '<choose a password>'
npm run dev                  # API http://localhost:9000 · admin http://localhost:9000/app
```

## Configuration (`medusa-config.ts`)
- **Secrets fail fast:** with `NODE_ENV=production` the server refuses to start unless `JWT_SECRET` and `COOKIE_SECRET` are random values of 32+ characters.
- **Redis is optional:** when `REDIS_URL` is set, the event bus, workflow engine and locking use Redis; otherwise Medusa's in-memory/Postgres defaults.
- `MEDUSA_WORKER_MODE=shared` runs API and background jobs in one process (best for one free instance).
- `DISABLE_MEDUSA_ADMIN=true` serves the API only.

## Free hosting — Render (free) + Neon (free) + GitHub Container Registry (free)

```
GitHub push ──► GitHub Actions builds the Docker image ──► ghcr.io/johnyumang/jrly-medusa
                                                               │ (pulled, no build on Render)
Neon free Postgres ◄── DATABASE_URL ── Render free web service (API + admin at /app)
```

| Piece | Free limit | What it means |
|---|---|---|
| Render web service | 512 MB RAM, 0.1 CPU, 750 h/month, 5 GB bandwidth | Sleeps after 15 min idle; first visit after that takes ~1 min to wake, a cold boot with migrations ~5–8 min |
| Neon Postgres | 1 GB storage, 100 CU-hours/month, no card | Suspends after 5 min idle; data is kept |
| GitHub Actions + GHCR | free for public repos | Builds the image on every backend change |

**Why this shape:** the admin dashboard build needs far more than 512 MB, so GitHub builds the image and Render only runs it. Render's own free Postgres is deleted after 30 days, so the database is Neon. Redis is optional and left off.

### One-time setup
1. **Neon** — sign up at neon.tech with GitHub → create project `jrly` (region Frankfurt) → copy the **direct** connection string (turn *Connection pooling* off) — it looks like `postgresql://…@ep-…eu-central-1.aws.neon.tech/neondb?sslmode=require`.
2. **Image** — runs automatically on push (Actions tab → *Medusa backend image*). If Render can't pull it: GitHub → your profile → **Packages → jrly-medusa → Package settings → Change visibility → Public**.
3. **Render** — sign up at render.com with GitHub → **New → Blueprint** → pick this repo → it reads `render.yaml` → fill in `DATABASE_URL` (from step 1), `ADMIN_EMAIL`, `ADMIN_PASSWORD` (12+ chars) → **Apply**. Secrets `JWT_SECRET` / `COOKIE_SECRET` are generated by Render.
4. First boot migrates, seeds 48 products and creates your admin. Open `https://<service>.onrender.com/app` and log in. The **publishable key** for the storefront is printed in Render → Logs (`Publishable key for the storefront`).
5. If Render named the service something other than `jrly-medusa`, update `ADMIN_CORS` / `AUTH_CORS` to the real URL.

### Boot behaviour (`docker-entrypoint.sh`)
On the first boot of each new image: `medusa db:migrate` → `src/scripts/bootstrap.ts` (seed once + admin from `ADMIN_EMAIL`/`ADMIN_PASSWORD`) → record the image version in table `jrly_boot`. Later wake-ups see the same version and go straight to `medusa start` on `$PORT`. `RUN_SETUP_ON_BOOT=auto` (default) \| `true` (always) \| `false` (never).

### Product photos
`npm run sync-catalog` (also runs before build/seed/dev) copies `../content/catalog.ts` → `src/data/catalog.ts` and `../public/stock/*.webp` → `static/stock/`. The image serves them at `/static/stock/…`; on Render the seed uses `RENDER_EXTERNAL_URL` for image URLs. Override with `IMAGE_BASE_URL`.

### Run the production image locally
```bash
npm run sync-catalog && docker build -t jrly-medusa .
docker run -p 9000:9000 -e DATABASE_URL=… -e JWT_SECRET=$(openssl rand -hex 32) -e COOKIE_SECRET=$(openssl rand -hex 32) \
  -e STORE_CORS=http://localhost:3000 -e ADMIN_CORS=http://localhost:9000 -e AUTH_CORS=http://localhost:3000,http://localhost:9000 \
  -e ADMIN_EMAIL=you@example.com -e ADMIN_PASSWORD='a-long-password' jrly-medusa
```

Never commit `.env`. Rotate secrets if they ever leak.
